# Day 7 — Kestrel-7 × VEXX 3.0

Day 6 was the right pivot — a real trainable transformer instead of a reference sketch — but its
pristine code failed 7 of 11 tests and carried 13 defects that made the model look better than it
was. Day 7 does two things in order: it repairs Day 5 and Day 6 so their suites pass, then it
promotes the parts of Kestrel that survive an audit into a **3:1 Gated DeltaNet hybrid** and puts a
**six-tier neuro-symbolic verifier** in the decode loop.

The organising rule is unchanged: a claim without a computed number and a falsifier is a slogan.

## Computed ledger

Every number below is produced by `tools/param_ledger_v7.py` (which instantiates each preset, calls
`sum(p.numel())`, and runs the benchmark), written to `metrics.json`, and re-derived in
`tests/test_kestrel7.py::test_param_and_cache_ledger_matches_models`. Nothing is transcribed.

| Preset | Layers | Mixers | Parameters | KV bytes @ ctx (fp16) | KV vs all-full |
|---|---|---|---|---|---|
| `TINY_DENSE` | 4 | 0 gdn / 4 full | **6,032,128** | **1,048,576** | 0.0% reduction |
| `TINY_HYBRID` | 4 | 3 gdn / 1 full | **6,250,192** | **262,144** | **75.0% reduction** |
| `SMALL_HYBRID` | 8 | 6 gdn / 2 full | **37,844,704** | **2,097,152** | **75.0% reduction** |
| `BASELINE_100M` | 12 | 9 gdn / 3 full | **105,062,040** | **12,582,912** | **75.0% reduction** |

Fixed recurrent state (not per token): `TINY_HYBRID` **125,952** bytes, `SMALL_HYBRID` **897,024**
bytes, `BASELINE_100M` **2,018,304** bytes at fp32 for batch 1.

The 75% figure is arithmetic, not a vibe: 3 of every 4 layers keep an O(1) state instead of a
per-token KV cache. For `TINY_HYBRID`, `2 × 4 kv_heads × 32 head_dim × 512 ctx × 2 bytes` per full
layer = 262,144 B; an all-full stack would pay 1,048,576 B. The alternative — all-full attention —
wins only if hybrid validation loss is worse at equal tokens and compute; that is the falsifier, and
on 50 steps it cannot be decided either way.

## TempBench (33 tasks, 48 points)

The evaluator scores **48 / 48 = 100.0%** over **33** tasks:

| Category | Points | Tasks | Verified mechanism | Status |
|---|---|---|---|---|
| Mathematics | 7 / 7 | 7 / 7 | restricted-AST SymPy: exact rationals, linear systems, modular pow, definite integral | implemented |
| Formal reasoning | 5 / 5 | 5 / 5 | exact Venn countermodel entailment (not satisfiability) + topo order | implemented |
| Code tracing | 4 / 4 | 4 / 4 | Tier-5 subprocess sandbox executes the snippet and observes the value | implemented |
| Code generation | 20 / 20 | 5 / 5 | Tier-5 verified synthesis: 4 unit tests per function, buggy candidates refuted | implemented |
| Science | 4 / 4 | 4 / 4 | closed-form computation (speed, molarity, Mendelian ratio, variance) | implemented |
| Research calibration | 8 / 8 | 8 / 8 | Tier 4: CI/p, supersession, poll bias, unverified entity, false premise, conflict | implemented (rule-based tripwire) |

> **VEXX/TempBench mechanism test: 48/48 on the current 33-task, 48-point custom suite.
> Not a Kestrel neural capability score.** The Kestrel-7 weights are not consulted
> for the answers, and the report says so. A separate neural evaluation must call
> the model directly and grade the generated output.

The answer key is regenerated by `independent_answer()` in `tools/eval_tempbench_v7.py`, which
uses separate implementations (fraction arithmetic, polynomial integration, permutation counting, a
separate boolean evaluator, and static human labels for calibration) rather than the solver path
being scored. `test_answer_key_is_independent_of_the_solver_path` re-derives every row and fails if
the two paths ever agree by construction. The old finite-universe check had returned `yes` for
"all A are B" ⇒ "all B are A"; the exact countermodel returns `no`.

This number measures the **pipeline** — CAS, countermodel checking, sandboxed execution, epistemic
guard — not the Kestrel-7 weights. The shipped model defaults to `randomly_initialized`; the
50-step run is a mechanism run, and the evaluator does not read a checkpoint at all. The evaluator
prints that caveat itself rather than letting the score imply otherwise.

Not implemented, and labelled as such: MTP self-speculative decoding (target only), a DPO training
loop over the collected pairs (collector only), on-policy reverse-KL RLVR (loss and tests only), and
a general factuality model behind Tier 4 (rule-based tripwire for the listed traps only).

## Run it

```bash
python3 -m pytest research/day6/tests/ -q          # 18 passed
python3 -m pytest research/day7/tests/ -q          # 35 passed
python3 research/day7/tools/eval_tempbench_v7.py   # 48/48 = 100.0%
python3 research/day7/run_kestrel7.py --preset TINY_HYBRID --steps 50
```

The run script deduplicates by SHA-256 before splitting, trains the tokenizer on the train split
only, trains+validates, writes a checkpoint whose config and tokenizer hashes are verified on
reload, and generates with VEXX active. Its 50 steps are a *mechanism* run: they prove the wiring is
real, not that the model learned anything.

## What would falsify this day

* Any cross-document logit difference above `0.0` under the block-diagonal mask (both attention and
  the GDN convolution are asserted).
* Streaming decode disagreeing with a full forward pass by more than `1e-4`.
* A checkpoint loading with a mismatched config or tokenizer hash, or resuming without its RNG
  state and batch cursor.
* An initialization with logit standard deviation far above 1 or an initial CE far above
  `ln(vocab)`.
* A tokenizer whose identity hash does not change when two token ids are swapped.
* A nonzero exact-match claim from a double-shifted label pipeline.
* A TempBench category below its declared point total, or an answer key that differs from the
  independent derivation.
